# ADR-001：术语与语义以代码实现为准

- 状态：已接受
- 日期：2026-10-27
- 上下文：single-context 域文档布局（根 GLOSSARY.md + docs/adr/）

## 背景

AM-001 设计文档、openapi 契约与现行代码已明显漂移：类型三值与「一切保存皆为待办」并存、ReminderRule 与 Reminder 并存、access_token 与 device_token 并存、文档 20 个动作与实现 8 个并存、ADR-010「首版不做 OCR」与已实装的 Vision OCR 矛盾等。README.md:56 本就写明「以运行指南和实际代码为准」。

## 决定

1. 术语与语义的裁决顺序为：**代码 > 运行指南（docs/RUN.md）> 设计文档 > 词汇表**；词汇表负责矫正文档语义，不回改代码去迁就旧文档。
2. 根目录 GLOSSARY.md 是唯一术语表：每个词条给规范词、中英对照、代码出处、状态标记（已实现 / 未实现 / 兼容保留 / 已过时）与禁用旧词。
3. 历史设计文档正文暂不逐字回改，以 GLOSSARY.md 的矫正表为准；新文档、新代码注释与 UI 新文案必须使用规范词。
4. 当前产品语义写死为「一切保存皆为待办（task）」；capture / memo 为兼容保留枚举。
5. 术语变更时同步更新 GLOSSARY.md；涉及语义转向时再新增 ADR。

## 后果

- 文档评审与代码评审可用同一把尺子，禁止再造同义新词。
- AM-001 中未实现的结构（SyncPage、回收站界面、20 个动作、ReminderOccurrence 等）一律按「未实现」对待，不得当作既有事实引用。
- AM-002 移植术语暂不纳入本表，落地时并入。

## 出处

维护者裁决（本会话，2026-10-27）：「按源码的实现为准，矫正语义」，随后对词表方案确认「按推荐」。
