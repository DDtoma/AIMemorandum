# 快捷记录与交互细节

## 1. 步骤怎样计算

将一次快捷键组合、一次点击或一次完整拖拽各计为一个操作；文字输入单独记录耗时，不把每个字符算作一步。第一次安装、系统授权、修改偏好不计入日常步数，但另设验收。所有指标都要实测，不代表已经达到。

| 路径 | 用户操作数目标 | 保存后 |
|---|---:|---|
| 文字随手记 | 2：唤起、Enter；另计输入 | 关闭快捷面板，回到原应用 |
| 文字直接待办 | 2：唤起、⌘Enter；另计输入 | 同上 |
| 区域截图 | 2：截图快捷键、框选并松手 | 自动保存，不再点击确认 |
| 剪贴板速存 | 1：速存快捷键；复制是前置动作 | 不打开完整面板 |
| 剪贴板粘贴并补充 | 3：唤起、粘贴、Enter | 可在保存前补一句话 |
| 拖入图片 | 面板已打开时 1 次拖放；未打开另加 1 次点击 | 自动保存一个 Item |
| 当前事项追加进展 | 打开事项后点击记录进展、保存，共 2 次 | 输入期间不跳页 |

## 2. 快捷键

| 快捷键建议 | 行为 | 默认 |
|---|---|---|
| ⌃⌥Space | 打开同一个面板并聚焦输入 | 注册，冲突则提示修改 |
| ⌃⌥S | 区域截图并记录 | 注册，首次使用才请求所需权限 |
| ⌃⌥V | 保存当前剪贴板支持的内容 | 注册，只在按下时读取 |
| Enter | 保存随手记 | 中文候选确认时不得提交 |
| ⌘Enter | 保存为待办 | 同样检查 marked text |
| Shift+Enter | 换行 | 不提交 |
| Esc | 取消框选或关闭面板 | 保留文字草稿；不创建空 Item |
| ⌘F | 进入搜索 | 输入框草稿保留 |

提供设置恢复默认和清空单个快捷键。不要为“选中文字”自动模拟复制或申请全局键盘监听权限。首版通过复制后速存实现；系统服务入口后续再做。

## 3. 三种保存模式只在入口区分

**编辑模式**：快捷面板内输入、粘贴图片、加链接，Enter 保存。未提交内容是草稿，不参与提醒；关闭或崩溃后可恢复。默认 capture，⌘Enter 创建 task。通过菜单栏点击打开的面板保存后保持打开；快捷键唤起的面板保存后收起；固定面板始终保持。

**直接记录模式**：专用截图、剪贴板速存、面板外层拖放，内容有效就保存 capture。短暂收条显示“已保存到本机”，提供“补一句 / 转待办 / 撤销”。不强制打开详情、不抢回焦点。收条消失后仍可从最新记录与历史进入。

**追加模式**：只有从某事项详情点击“附加截图/图片”才向该 Item 追加；全局截图永远新建，避免记错到之前的焦点事项。追加操作携带原事项版本，冲突时保留图片和本地修改。

## 4. 截图的完整流程

```text
截图快捷键
 → 检查当前权限；必要时显示用途说明和系统授权
 → 隐藏自己的面板，显示区域选择层
 → 用户拖拽框选，松手
 → 获取所选区域单帧，编码 PNG
 → 写入本地文件并校验
 → SQLite 事务保存 Item、Attachment、Outbox
 → 显示“已保存到本机”收条，返回之前应用
 → 后台同步文字元数据和图片
```

首版主路径是区域截图；窗口截图放在截图按钮菜单中，用系统选择器选择窗口。全屏截图可作为菜单选项，无默认全局键。初始截图格式 PNG，保留可读像素；不得静默缩小代码或报错文字。

| 情况 | 具体行为 |
|---|---|
| 用户按 Esc/选择器取消 | 不创建事项，恢复原草稿和焦点 |
| 零尺寸或过小区域 | 继续选择，不保存空白文件 |
| 权限被拒绝 | 保留其他记录方式；提供“用系统截图后粘贴”提示，不循环申请 |
| 获取图像失败 | 不显示保存成功；允许重试，返回原工作 |
| 文件写入失败/磁盘满 | 显示尚未保存；尽可能保留内存预览供重试或另存，不能承诺崩溃后可恢复 |
| 锁屏/受保护内容/黑图 | 返回系统错误或提示检查预览；不声称能绕过保护；不依靠 OCR 判断成功 |
| 连续按键 | 捕获进行中只保留当前会话，不并发开多个选择层 |
| 双屏不同缩放 | 单次区域限制在开始框选的屏幕；边界可见，不截取未选屏幕 |
| 原来有未保存草稿 | 截图另存新 Item；草稿不被清空、不合并 |

权限与窗口行为要在实际最低系统版本和一个发布时维护的较新版本上验证。使用 ScreenCaptureKit 单帧截图；区域选择只是矩形输入，不冒充系统窗口共享选择器。系统选择器支持选择窗口/显示器，不能假设它自带区域框选。[Apple 的截图与选择器介绍](https://developer.apple.com/videos/play/wwdc2023/10136/)

## 5. 粘贴、速存和拖入

剪贴板只在用户粘贴或触发速存时读取，不轮询、不保存历史。不主动读取密码管理器中的内容；能识别的密码/保密类型不做速存并提示用输入框手动记录，但不能保证所有应用都提供这种标记。

同一剪贴板常有多个表示：图片表示优先于该图片附带的文件 URL；否则采用明确文件列表，再采用纯文本。文件只接受 PNG/JPEG；普通 URL 作为文字链接；HTML 转纯文本，首版不保留网页脚本或样式。复制的一张图片不能分别创建图片事项和文件路径事项。

空剪贴板、未知格式、超限图片显示原因，不创建空记录。一次最多 10 张图片，每张最多 20 MiB、40 百万像素；一次记录附件总量最多 50 MiB。这些为首版建议限制，在界面可见，拒绝不能悄悄丢掉部分图片。

拖放目标明确区分：面板外层“放开即保存”创建新 Item；输入框中的附件区域加入当前草稿；详情中的“添加附件”加入当前 Item。拖入多张图片合成一条 capture，保留拖入顺序；不要创建十条单独的催办记录。

PNG/JPEG 从文件拖入后复制到应用管理目录，原文件移动不影响已保存内容。其他文件首版只可作为“本机文件引用”，经用户明确选择后保存书签/路径与所属设备；不上传文件内容，在别的设备显示“位于另一台设备”。

速存防误按：相同 pasteboard changeCount、同一内容指纹，2 秒内重复触发只返回上一次收条；2 秒后再次主动记录允许新建。普通记录不做全局内容去重，避免吞掉有意重复的事项。operation_id 用于网络重试去重，和此交互防抖不是同一机制。

## 6. 提醒的最少操作

记录默认不设时间；保存后可从收条点“稍后提醒”，选择明确时间后将 capture 转 task 并创建提醒，单次领域事务提交。快捷选项保存前必须显示具体时间；“今天稍后”建议默认两小时后，但跨日时显示真实日期，不隐藏变化。

已有待办的“明天处理”只改 planned_for；“稍后提醒”只改所选提醒规则；截止时间保持。截图默认不设置提醒，依赖待整理回顾；对某张截图有明确跟进要求时再设提醒。

## 7. 无障碍与焦点

所有按钮有可读标签、键盘路径和 VoiceOver 描述；状态不能只靠颜色。输入法候选、日期选择、文件选择、截图系统选择器占用焦点时，不把失焦当作丢弃草稿的理由。

快捷键打开时记住前台应用；保存/取消后只尝试恢复那一个仍在运行的应用。用户已主动切去第三个应用时不强行抢回。正文支持系统听写输入；输入法 marked text 和听写尚未提交文本均不触发保存。

## 8. 首次使用

第一次打开就可输入并本机保存。设置页逐项提供连接服务端、快捷键、登录启动、隐私预览；通知权限在首次创建提醒时请求，截图权限在首次截图时请求。任何拒绝都不影响文字本机记录。不上来就索取屏幕、麦克风、辅助功能和通知的全部权限。
