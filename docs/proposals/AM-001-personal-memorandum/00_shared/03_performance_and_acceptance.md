# 性能与验收标准

所有数值都是待测工程目标，当前没有运行基线。P0 是首版发布门槛，P1 是首版完整性验收；不能用 P1 的名称长期省略核心功能。明确延期需更新范围与任务表。

## 1. 性能测试条件

建议基准机为 Apple Silicon M1、16 GiB RAM、SSD；具体 Mac 型号、macOS、Xcode 构建、可用磁盘与电源模式在第一次测试时记录。最低 macOS 14 与发布时维护的较新系统各测一组；Intel 若宣称支持则另加实机结果。服务端基准 2 vCPU/4 GiB/SSD。

数据集：10,000 个 Item，平均正文约 1 KiB，30% 含中文、10% 含命令/代码；1,000 张图片，每张 2–5 MiB；100 个有效未来提醒、500 个回顾候选、100 个等待事项。另设 100 KiB 长正文和 20 MiB 图片边界集。

| 指标 | 目标 | 测量边界 |
|---|---:|---|
| 已运行应用面板打开 P95 | ≤200 ms | 热键/点击回调 → 输入框可输入且首屏列表可交互，500 次 |
| 文字保存 P95 | ≤100 ms | 提交 → SQLite commit + 成功收条，1 KiB 文本，500 次 |
| 截图保存 P95 | ≤800 ms | 框选松手 → 图片持久化 + SQLite commit，单屏 2560×1440、PNG ≤10 MiB，100 次；不含授权与框选耗时 |
| 搜索 P95 | ≤150 ms | 查询提交 → 第一页结果渲染，不含输入防抖；含 1–2 字中文与字面代码，200 次 |
| 服务端元数据写入 P95 | ≤150 ms | API 收到完整请求 → 提交结果，不含网络与图片传输，10 req/s 持续 10 分钟 |
| 前台在线变更可见 P95 | ≤3 s | 服务端提交 → 另一在线客户端显示，RTT 50 ms、无注入故障 |
| 到期状态计算 P95 | ≤5 s | occurrence_at → 服务端 durable due 状态；不代表系统弹窗耗时 |
| 常驻空闲 CPU | 5 分钟均值 ≤1% 单核 | 无同步/截图/索引任务时；报告同窗内存，不伪造目标通过 |

冷启动、首次全量同步、索引重建单独报告，不混入面板热打开目标。1 MiB 附件弱网吞吐与整图重试流量单独记录，不设不现实的固定同步秒数。任何性能未达标先给原始样本和瓶颈，不删掉准确保存或短词搜索兜底来“通过”。

## 2. 快捷记录与原生交互

| AC ID | 优先级 | Given / When / Then |
|---|---|---|
| AC-CAP-001 | P0 | Given 应用已运行且离线；When 快捷键输入文字后 Enter，立即强制退出再启动；Then Item 和同 operation_id 的 Outbox 仍存在，无分类/日期步骤 |
| AC-CAP-002 | P0 | Given 截图权限已允许；When 热键后框选松手；Then 无额外确认自动保存 capture、PNG 与 Outbox，可不填标题；记录路径为 2 个操作 |
| AC-CAP-003 | P0 | Given 正在中文候选确认或系统听写未提交；When Enter/⌘Enter；Then 只确认文本，不生成 Item；Esc/失焦后草稿保留 |
| AC-CAP-004 | P0 | Given 剪贴板含图片及其其他表示；When 速存，并在 2 秒内误按一次；Then 仅创建 1 个 capture 与 1 个图片引用，后台不持续读取剪贴板 |
| AC-CAP-005 | P0 | Given 图片已写完但本地事务前崩溃，或事务后收条前崩溃；When 重启；Then 固定捕获会话最多恢复 1 个 Item，不丢可恢复原图，不重复入队 |
| AC-CAP-006 | P0 | Given 权限拒绝、Esc 取消、磁盘满、无效或超限图片；When 尝试记录；Then 不显示虚假成功、不清除原草稿；给出对应重试/粘贴入口 |
| AC-CAP-007 | P1 | Given 面板有草稿；When 多图拖外层或粘贴输入框；Then 外层自动新建 1 条，输入框追加草稿；10 张/20 MiB/40 百万像素/总 50 MiB 边界被一致执行 |
| AC-MAC-001 | P0 | Given 副屏、不同缩放、全屏 Space、快捷键冲突和日期子窗口；When 唤起、框选、保存、关闭；Then 图像范围正确，冲突可改键，焦点不误关草稿，关闭不退出应用 |

## 3. 事项、回顾、检索

| AC ID | 优先级 | Given / When / Then |
|---|---|---|
| AC-DOM-001 | P0 | Given waiting 且 review_at 到期；When 打开面板/服务端计算；Then 进入需要关注；收到结果回到 todo，保留下一步；外部执行成功不直接 complete |
| AC-DOM-002 | P0 | Given 无日期 task、纯截图 capture、无复查时间的 paused；When 日常回顾分批处理；Then 三者均可出现，显示总量并按稳定顺序轮换；查看/搜索不更新进展 |
| AC-DOM-003 | P1 | Given 进行中有进展和下一步；When 隔天回来、切换焦点、完成再撤销；Then 可恢复上下文，多个进行中合法，撤销有版本校验和历史 |
| AC-SEARCH-001 | P1 | Given 中文、命令、代码与仅图片数据集；When 搜索“超时”“库”“reasoning_effort”“--flag”“%”；Then 字面命中正确，不把标点解释为查询操作；未 OCR 图片不声称有文字命中 |

## 4. 同步与附件

| AC ID | 优先级 | Given / When / Then |
|---|---|---|
| AC-SYNC-001 | P0 | Given 服务器已提交但响应丢失；When 相同操作重试 20 次；Then 只有一个 Item/事件/操作凭据的业务效果，返回原确认；同 ID 改内容返回冲突 |
| AC-SYNC-002 | P0 | Given 两台设备基于 revision=7 改正文；When 并发提交；Then 只有一方成功，另一方保留全文与附件，不自动最新版本覆盖；后续本地依赖操作暂停 |
| AC-SYNC-003 | P0 | Given 两事务交错开始且第一个提交被延迟；When 增量分页并在每个阶段拉取；Then 不漏任何已提交变更；应用数据与 cursor 同事务 |
| AC-SYNC-004 | P0 | Given 删除记录过期且本地有旧编辑/待上传图片；When 过期 cursor 拉取快照；Then 本地稿件和 Outbox 保留，旧 ID 不复活，可另存 |
| AC-SYNC-005 | P0 | Given 服务端从较早备份恢复并更换 epoch；When 客户端重连；Then 先重建影子快照，旧操作等待确认，不盲目重放完成/删除/改期 |
| AC-ATT-001 | P0 | Given 元数据已确认、图片中途断网或服务器文件写入后崩溃；When 重试上传；Then 相同文件只关联一次，哈希一致才 ready，界面不能提前显示全部已同步 |
| AC-ATT-002 | P0 | Given 附件上传时原 Item 被删除或无权访问；When 上传提交/下载；Then 重新鉴权和检查关联，拒绝失效上传，不泄露原图；失败原图仍留本机 |

## 5. 提醒

| AC ID | 优先级 | Given / When / Then |
|---|---|---|
| AC-NOT-001 | P0 | Given 已登记提醒；When 关闭通知、打开通知或稍后提醒；Then 不完成 Item；稍后只改所选 reminder，不改变 due/planned/review |
| AC-NOT-002 | P0 | Given A 完成且 B 持旧版本提醒；When B 提交稍后提醒或点击旧通知；Then 不产生新有效提醒；联网校正取消旧 pending，离线旧通知边界有说明 |
| AC-NOT-003 | P0 | Given 未来提醒已登记，通知权限关闭、应用退出、睡眠或服务端重启；When 到期与恢复；Then 数据不丢，权限状态可见，遗漏汇总可查，不逐条补发通知风暴 |
| AC-NOT-004 | P0 | Given 日期截止、精确截止、跨时区与 DST 边界；When 午夜/时区改变/选择歧义时刻；Then 日期语义保留，时间点一致，歧义明确处理；登记成功不标为已看 |

## 6. 安全、接口与运维

| AC ID | 优先级 | Given / When / Then |
|---|---|---|
| AC-AUTH-001 | P0 | Given 两个测试 owner、撤销设备、仅追加进展凭据；When 伪造 owner/source、访问图片/快照/导出或结束事项；Then 越权全部拒绝，日志无正文和令牌 |
| AC-OPS-001 | P0 | Given 已含图片、事件、待同步修改的服务；When 备份并在空环境恢复、导出 ZIP；Then 记录数和图片哈希符合 manifest，恢复演练验证 RPO/RTO，导出缺图明确报出 |
| AC-API-001 | P0 | Given v1 契约和不支持的枚举/动作；When 请求空白记录、互斥截止、过期操作、未知写字段；Then 返回稳定错误；旧客户端保留未知只读数据、不降级覆盖 |
| AC-PERF-001 | P1 | Given 第 1 节的固定环境和数据；When 按指定样本执行；Then 每项报告 P50/P95/最大值和原始样本，达到目标才记通过 |

## 7. 发布证据要求

验收记录至少包含构建 SHA、OS/硬件、数据库版本、测试数据种子、执行命令、结果文件、失败复现和责任人。真实 OS 行为保存短视频或截图及步骤；不得用模拟 NotificationClient 测试代替系统授权、退出后通知和唤醒测试。所有 AC 当前均为“待执行”。
