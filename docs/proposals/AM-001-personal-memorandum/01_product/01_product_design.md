# 产品设计

## 1. 用户要解决的事情

产品同时回答：还有什么没结束、什么时候再看、回来从哪里继续。主要用户为同时处理开发、文档、个人事务和外部执行结果的个人；首版单账号、多设备协议，实际发布 Mac 客户端。

成功的表现是：想到的事情能立即保存；截图不需要再抄一遍；等结果的事情能按时回来；打开事项能看到下一步。保存量、提醒次数都不能单独作为产品成功指标。

## 2. 信息结构

| 类型 | kind | 行为 |
|---|---|---|
| 随手记 | capture | 未整理内容，包括纯截图；进入待整理回顾 |
| 待办 | task | 有预期结果；参与状态、时间和进展 |
| 普通备忘 | memo | 用户明确选择只保存；搜索、分组、关联，不催办 |

所有内容都是 Item。纯图片 Item 合法，系统给出“截图 · 10月13日 14:20”这样的可编辑显示标题，记录标题来源为 generated；生成标题不表示理解图片。空文字且没有有效附件不能保存。

一个 Item 最多属于一个可选分组；同组可放三种类型。首版无多层项目、标签体系和优先级表单。Markdown 检查清单保存在正文中；子步骤需要独立等待或提醒时，由用户执行“转为独立事项”，生成新 Item，保留原文和 related_item 引用。

### 状态

task_state 为 todo、in_progress、waiting、paused、completed、canceled；仅 task 有 task_state。未结束状态间可切换。终态需显式“重新打开”才能回到 todo。完成设置 completed_at；取消设置 canceled_at；重新打开清空当前终态时间，历史仍保留。

等待必须描述 waiting_for，可选择 review_at，也可选择“放入日常回顾”；暂停同样不能消失，未设置复查时间时进入日常回顾。“收到结果”是显式动作：waiting → todo，清除等待复查安排，保留历史和 next_action，不完成事项。

capture 可以一键变为 task 或 memo；task 转 memo 会结束任务关注、撤销提醒并保留历史。memo 转 task 默认 todo；用户在明确提醒入口为 memo 设置提醒时，该入口明确显示“转为待办并提醒”，确认设置时间即完成转换，无额外确认弹窗。

## 3. 菜单栏与首页

默认简洁图标，有当前需要关注的内容时显示标记。数量可选，仅计算去重后的“需要关注”Item，不计全部未完成。普通备忘、尚未到复查时间的等待、未来计划项不占数量。

面板建议宽 420 pt，常规高度约 600 pt，随可用屏幕调整。内容顺序：

1. 快速输入框；附有小型截图、粘贴和时间按钮，主按钮只有保存。
2. 当前接着做：最多一个焦点事项，显示进展和下一步；不限制其他进行中事项。
3. 需要关注：到期、到跟进时间、计划到今天及以前、尚未处理的明确提醒；每条说明原因。
4. 待整理和日常回顾：显示总数与“回顾 N 条”，默认折叠。
5. 等待中：显示总数，可展开。
6. 搜索、全部事项、同步与设置入口。

一条事项有多个关注原因，只算一次，详情展示全部原因。首页只显示前 5 条时，必须显示“还有 N 条”。当前焦点在本机维护，设备间不互相抢焦点；焦点事项完成、取消或删除后清除。

点击条目在同一个面板进入详情，返回保持滚动位置。长文本可展开同一编辑内容为大窗口，使用同一个数据模型和草稿；不建第二套工作台。默认无 Dock 主窗口；关闭面板不退出应用。固定面板是显式开关，默认不固定、不置顶。

## 4. 详情与最短动作

常驻显示标题、正文/图片、下一步、当前进展；其余信息按需展开。待办详情底部的主动作随状态变化：

| 当前情况 | 主动作 | 次动作 |
|---|---|---|
| 待处理 | 开始 | 等待、设置时间、完成 |
| 进行中 | 记录进展 | 等待、完成 |
| 等待中 | 收到结果 | 继续等待、改跟进时间 |
| 暂停 | 继续 | 改复查时间 |
| 已完成/已取消 | 重新打开 | 历史、删除 |
| 随手记 | 转待办 | 仅作备忘、删除 |

“记录进展”只用一个常显的“下一步”输入框，展开后补进展和链接；任一内容非空即可保存。切换焦点时可出现一次不阻断的提示，用户不输入也能切换。

“等待”展开内联表单：等什么、什么时候再看；下一步可选。提供“30 分钟后、今天稍后、明天、选择时间、日常回顾”。涉及时间的选项旁显示解析后的精确日期、时刻和时区；预选不等于提交，点击“进入等待”一次保存。默认只在面板跟进；“同时通知我”由用户选择，只有选了具体时刻才能开启，状态和这条跟进通知一次提交。收到结果后撤销对应跟进通知，独立设置的其他提醒保留。

列表完成按钮一次生效，收条提供撤销。通知点击“完成”同样属于用户的明确完成操作；关闭通知、点击正文或选择稍后不完成。

## 5. 时间与回顾规则

| 字段 | 语义 | 展示规则 |
|---|---|---|
| planned_for | 计划处理的日期 | 当地日期，不带伪造时刻 |
| due_date 或 due_at | 最晚完成日期或时刻，二选一 | due_date 当天显示今天截止，次日才逾期 |
| review_at | 再检查或跟进的绝对时刻 | 到时加入关注；不必发送通知 |
| reminder_rules.remind_at | 用户明确设置的一次通知 | 单独设置；稍后提醒只变更此规则 |

日期解释采用事项 timezone，不随设备旅行偷偷变化。精确时刻用 UTC 传输，同时保留 IANA 时区用于展示。跨时区时同时标出事项时区和当前设备时区，日期型截止不转换成 UTC 午夜。日常回顾使用账号的 home_timezone，默认在首次设置时取本机时区，之后不自动改动。

确定性回顾规则（首版默认值，设置可修改）：

| 情况 | 再出现规则 |
|---|---|
| capture 未整理 | 下一次日常回顾候选；无须日期 |
| 未结束 task 没有任何未来安排 | 日常回顾候选 |
| waiting/paused 有 review_at | 到期进入需要关注；不等待下一次日常回顾 |
| 有计划日期 | 日期到达后保持需要关注，直到用户改期或结束 |
| 进行中 7 天无进展 | 加入日常回顾；保留其原有日期 |
| 完成/取消/memo/删除 | 不参与关注和回顾 |

日常回顾页面随时可打开；合并通知默认关闭，用户可设每天一次的时间。候选按 last_reviewed_at 空值优先、时间升序、created_at、id 排序，每批 10 条，始终显示总数。“继续保留，明天再看”是明确回顾动作，更新 last_reviewed_at 与 next_revisit_on；只打开、搜索或略过不算回顾，不改变 last_progress_at。用户可继续看下一批，不能只能访问首批。

回顾操作：今天做、设复查、继续等待、转备忘、取消、明天再看。due_at 已逾期的事项不能因“明天再看”从需要关注消失；任何一个到期原因仍成立，条目就保留。未来通知只能覆盖“无安排”条件，不能压掉逾期或已到复查时间的原因。

## 6. 通知与故障呈现

通知动作：完成、稍后提醒；点击通知打开事项。按钮实际呈现由系统决定。隐私默认只显示“有一件事项需要关注”；用户可打开标题预览，不展示截图缩略图或全文。

| 状态 | 用户看到什么 | 可做什么 |
|---|---|---|
| 本地已保存、尚未上传 | 已保存到本机 · 待同步 | 继续工作 |
| 文字已同步，图片未上传 | 文字已同步 · 图片待上传 | 查看本地图片，手动重试 |
| 全部被服务端确认 | 已同步 | 无额外操作 |
| 失败 | 同步失败 · 原因摘要 | 重试、重新授权、查看失败项 |
| 冲突 | 有两个版本待处理 | 保留本地、使用服务端、手工合并、另存副本 |
| 通知权限关闭 | 通知未开启 | 去设置；需要关注仍保留 |

首次启动无需登录就能本机记录；服务端连接、设备授权、登录启动、通知权限按使用时机提供。首次配置同步时说明文字和截图会同步到所配置服务端；不把这层告知重复插入每次保存。

## 7. 搜索、历史、撤销与删除

搜索覆盖标题、正文、下一步、进展、等待内容和用户为图片写的说明；纯截图在未加入 OCR 前只能通过标题、时间、类型或人工文字找到。不能宣传首版能按图片中文字搜索。

默认不显示删除项；可选择已完成、已取消和回收站。搜索结果显示类型、状态、命中片段和图片缩略图。链接默认由用户点开，不自动访问、预取网页或执行命令。

撤销是带版本校验的反向操作，不是修改历史。已出现远端修改时进入冲突处理。回收站默认保存 30 天，删除立刻退出关注并撤销通知；恢复保留原状态，过期提醒不逐条补发，进入遗漏汇总。清空回收站需要明确确认，清空后备份按其保留周期到期，不承诺立即从所有历史备份消失。

## 8. 第二批功能边界

后续可增加：本机 OCR、分享扩展、选中文字的系统服务、图片裁剪与遮盖、语音附件、重复事项、跨平台客户端、Agent 适配。OCR 只增加派生检索内容，不创建待办、日期或完成状态。新增记录入口仍复用同一保存管线，不各自建立独立收件箱。
