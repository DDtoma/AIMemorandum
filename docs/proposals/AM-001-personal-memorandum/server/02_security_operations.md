# 身份、安全、部署与恢复

## 1. 单用户设备授权

首次通过服务器管理命令创建唯一 owner 与短期一次性注册码；建议 10 分钟过期、至少 128 位随机熵，失败尝试限速。注册码由使用者输入 Mac，换取 256 位随机设备令牌；不得把注册码写进公开日志、URL 查询参数或提交进 Git。生产环境只接受 HTTPS。

令牌存 Keychain；服务端保存哈希，按请求查设备是否撤销与允许 scope。每台设备独立令牌，可命名、查看最后使用时间和撤销。撤销后停止上传与下载，本地已经存在的内容不能被远程撤销“擦除”；界面允许用户导出或明确清除本机数据。

开发环境可允许显式配置的 localhost HTTP；正式构建不能默默降级 TLS，也不关闭证书校验。凭据只通过 Authorization 传递；SSE 同样鉴权，不把令牌放 URL。

未来 Agent 令牌独立配置 scopes；追加进展不等于允许完成，读取 Item 不自动允许下载所有附件。服务端 actor 包含 actor_type/device_id/integration_id（适用项），请求 source 不能冒充这些身份。

## 2. 本机与图片隐私

屏幕只在用户主动截图时采集；剪贴板只在用户粘贴或速存时读取。不开启全时屏幕录制、窗口标题采集、剪贴板历史、麦克风或跨应用自动复制。权限用途说明使用实际用途，不借“方便”申请无关权限。

图片包含的敏感内容和原图元数据随同步上传到用户配置服务端；首版不声称自动识别或遮盖密码。通知默认隐藏内容，截图收条仅在当前桌面短时显示缩略图，可在设置中改为纯文字收条。

本地数据库与图片依赖操作系统账户权限和磁盘保护；支持 Keychain 不等于数据库加密。服务器可采用加密磁盘与加密备份；本方案未设计客户端持钥的端到端加密，因此不能宣称 E2EE。

## 3. 部署基线

建议测试规格：服务端 2 vCPU、4 GiB RAM、SSD；PostgreSQL 选实现时仍受维护的稳定版本并固定镜像摘要，Go 和 Xcode 版本在 Phase 0 锁定。规格用于测量，不是容量保证。

```text
TLS 入口 :443
   → memorandum-api（非 root，只有 API 端口）
       → PostgreSQL（仅内部网络）
       → /var/lib/memorandum/blobs（持久卷）
       → /var/lib/memorandum/staging（同文件系统，支持 rename）
备份作业 → 独立故障域的加密备份存储
```

Compose 需健康检查、restart 策略、资源边界、数据库凭据 secret 文件、附件卷与磁盘余量告警。升级先执行兼容迁移，后替换应用；破坏性迁移不能与可回滚旧版本同时发布。迁移失败中止升级，不清库重试。

配置包含 listen_addr、database_url、blob_root、public_base_url、附件限制、job_poll_interval、retention_days、backup_destination、sync_epoch。配置校验启动时完成；secret 不能输出到启动日志。

## 4. 备份的内容和频率

建议首版每小时一次一致备份，RPO 目标不超过 1 小时、RTO 目标不超过 2 小时，必须以一次真实恢复演练验证；备份失败或超时会使实际 RPO 超过目标。最近尚未同步的本地修改不属于服务端备份。

备份包含数据库、所有 ready 附件、需要恢复的事件与操作凭据、schema 版本、校验清单和关键配置；凭据签名密钥另行安全保存。保存 48 个小时版本、30 个每日版本是建议策略，容量不足必须调整频率/保留并告知影响。

数据库与文件一致性：图片不可变、先文件后 DB。备份期间暂停附件 GC，先获取数据库一致快照并导出该快照内 ready 附件清单，再复制清单中的文件，校验 SHA-256。完成后才标记备份成功并恢复 GC。不能只备份 PostgreSQL，因为截图内容在独立卷。

## 5. 恢复演练步骤

1. 在隔离环境恢复数据库和附件清单对应文件，核对 Item 数、事件数、附件数量和全部附件哈希。
2. 检查 schema/app 版本匹配；扫描 DB ready 但文件缺失的异常，任何缺失阻止宣布恢复成功。
3. 生成新的 sync_epoch；清除临时租约，恢复后台任务；同步进入恢复模式。
4. 启动客户端，验证它看到 epoch 变化并保留本地 Outbox，获取新快照；恢复点之后的数据列为待确认，不自动覆盖。
5. 验证已完成项不产生新提醒、待跟进项仍能出现、截图能下载打开。
6. 用户确认恢复完成后切换流量；记录恢复所用版本、恢复点、耗时、数据缺口。

客户端自身损坏：先复制损坏数据库、Outbox 和文件到 recovery，再修复或重建；不能先清空再从服务端同步，因为尚未上传的数据可能只在本机。

## 6. 导出

客户端“一键导出”产生 ZIP，含 manifest.json、items.json、每项 Markdown、attachments/ 原图、事件 JSON（用户可选）；图片相对链接，原始时间语义与状态保留。文件名使用 Item ID 加安全短标题，防止路径穿越。正常文本导出不把 access token、设备密钥或本机书签写入包。

导出本机视图时包含待同步和冲突内容并在 manifest 标记，不能假装等同服务端快照。服务端导出通过后台任务生成一致快照；下载端点鉴权、短期保留，未完成返回状态。导出检查链接指向的每张图片都在包中；缺图需显式列出，不能返回“完整备份”。导出为可迁移资料，服务端灾难恢复仍使用上节备份流程。

## 7. 可观测与故障处理

指标：本地保存失败数、最老 Outbox 年龄、冲突数、附件待上传字节、服务端写入 P95、到期任务延迟、工作失败数、最近备份成功时间、附件校验失败数。指标不带正文或截图。

建议告警：备份超过 2 小时未成功；磁盘可用空间低于 15%；到期工作持续 5 分钟未推进；附件哈希错误非零。用户软件只对可操作状态提示，不反复弹出同一网络错误。

## 8. 发布检查

实际签名包验证 Keychain、通知、截图授权和登录启动；旧客户端读取新增可选字段；数据库升级失败回滚；断网、崩溃、响应丢失与备份恢复。只完成文档、单元测试或浏览器示意均不能通过发布门槛。
